# x-scout

Local app: searches X for up to 10 topics through a real Chrome profile (Playwright), scores posts for early virality (ported from github.com/Sentimenta1ist/x-viral-radar `scoring.js`), then one `claude -p` call per topic (3 in parallel) picks up to 6 posts to reply to and 6 to read, each with a breakdown (gist, context, why, why it spreads, what to take, doubts, say/ask replies). UI is FastAPI + one vanilla-JS page.

- `x_scout/browser.py` Playwright, persistent profile in `data/browser-profile`. Reads X's own `SearchTimeline` GraphQL responses, never the DOM. Keep it human-paced (randomized pauses, few scrolls); stop on 429 or login redirect, but a 429 after some posts were read keeps them and the run is still analyzed. No clicks, likes, follows, posting. Per topic, all over the last day: main query Top + Latest, plus one Top search per extra query (`topic.extra`, Claude writes 3 when the key is absent). Wider net, not a longer window: older posts repeat between daily runs.
- `x_scout/parse.py` GraphQL → flat post dict. X moves fields between schema versions; look up new place first, then legacy.
- `x_scout/scoring.py` pure scoring, tests in `tests/`.
- `x_scout/analyze.py` candidate pre-filter, compact pipe-delimited digest (with reach = views/followers and bm = bookmarks/like), `rank_topics` runs `claude -p` per topic with a short custom system prompt, `--tools ""`, `--setting-sources ""`, empty cwd; a failed topic falls back to local ranking. Output is a header line per pick (`R n q`) followed by field lines (`GIST`, `CONTEXT`, ...); the old one-line format still parses. Quality over tokens, but measure `usage` after prompt changes.
- `x_scout/pipeline.py` orchestration and live state; `app.py` HTTP API.
- Profile analysis (one X account, the Profiles section of the left sidebar; new features get their own sidebar item via `VIEWS` in `app.js`): `browser.scrape_profile` reads `UserByScreenName` + `UserOriginalsTimeline` / `UserRepliesTimeline` JSON (X renames these; see `POST_OPS`, `REPLY_OPS`) in the same Chrome session, `parse.py` (`profile_from_user`, `timeline_page`, `finalize_timeline`) flattens it, `profile_metrics.py` is pure local metrics (breakout = views >= 5x the median of the 30 previous original posts), `profile_analysis.py` is the one `claude -p` call (line format, always `profile_model`, default sonnet, independent of the search model), `profile_store.py` handles `data/profiles/<handle>/`, `static/profile.js` is the section. Shares `pipeline.state`, `_busy` and Stop with topic runs (`state.kind`). Stop / 429 / lost session keep the partial scrape without calling Claude. Re-analyze uses the stored scrape: use it for prompt tuning. Growth phases are inference from views, keep them labeled so.
- Post analysis (Post section): `post_analysis.parse_ref` takes a link or text, `browser.scrape_post` opens the post once and finds it in any `*Tweet*` GraphQL response (`parse.post_detail`, including Article bodies and the author's thread), one `claude -p`; `static/post.js`; records in `data/posts/`. Pasted text never opens X. DRAFT lines may use only the reader's own stories.
- Topic picks: `analyze.assemble` shows only q >= 4 and sends replies without reach (`has_reply_reach`) to Read; empty columns are expected, never fill them. During a run the UI stays on the run being viewed and opens the new one when it finishes.
- Sidebar sections are `VIEWS` in `app.js`: Topics, Profiles, Post, Settings. Keep first screens short: details go in a folded section (user feedback: Profiles was overloaded, then the Topics board too). Topics is one quiet column (`pick()` in `app.js`): meta line, gist as headline, why, replies; context, spread, take, doubt, full text and numbers fold out. `card()` stays for Profiles and Post.
- `data/` (gitignored): sqlite db, browser profile, `settings.json`, `profile.md`, `profiles/`, `posts/`. Never commit it.
- Tests: `uv run pytest`. Run: `./run`. Demo data: `scripts/demo.py`; README images: `scripts/screenshots.py` against a demo server.
- Re-analyze (UI button / `POST /api/runs/{id}/reanalyze`) re-runs Claude on stored candidates without scraping: use it for prompt tuning.
